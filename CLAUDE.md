# CLAUDE.md — chatwoot-mcp

**Company context comes first: read [../mojood-master/CLAUDE.md](../mojood-master/CLAUDE.md) and
[../mojood-master/STATUS.md](../mojood-master/STATUS.md), then this file.** Never add a `Co-Authored-By` line (or
any Claude attribution) to a commit message or a pull request description.

**What's here:** a Mojood Connect demo, built for one company (Chatwoot Inc.) to show them their product working
inside Claude. Six tools over Chatwoot's REST API; the two that change conversations need a confirmation code (`tools.py`);
no tool sends a message to a customer. A local Chatwoot in Docker (`docker/compose.yml` follows Chatwoot's production compose, pinned;
`scripts/up.sh`, `scripts/setup.rb`, `scripts/reset.sh`) holds the SAMPLE customer inbox
of the made-up Harbor Trading (`seed.py`, times set by `scripts/backdate.rb`). Private until Hammad sends it; public
(Apache-2.0) after. Same recipe as `../snipeit-mcp`.

## Commands
```
scripts/reset.sh                         # fresh local Chatwoot + SAMPLE inbox (Docker via Colima: `colima start`)
uv run --env-file .env chatwoot-mcp      # http://127.0.0.1:8004/mcp ; add --stdio for Claude Desktop
uv run --env-file .env pytest            # unit tests + live tests against the local Chatwoot
uvx ruff check --line-length 120 src tests
```

## Rules
- Secrets (`.env`, `docker/.env`: the API token, the admin and database passwords) are generated by `up.sh`,
  git-ignored, and never printed, copied into docs or chat.
- Everything in the data is SAMPLE and made up; no real company's data goes in.
- A change tool never acts without its confirmation code; keep the tests in `tests/test_tools.py` passing.
- The API token is the admin user's access token: `GET /api/v1/profile` returns it, so never print that response.
